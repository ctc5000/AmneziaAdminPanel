# Amnezia VPN Control Panel

Веб-панель для мониторинга VPN-серверов Amnezia: отслеживает **состояние
Docker-контейнеров** и **список подключённых пользователей** (клиентов) на
каждом сервере.

Работает так: панель по SSH заходит на сервер, выполняет команды `docker` и
`awg`/`wg`/OpenVPN-status, парсит вывод и показывает результат в браузере.

## Возможности

- Добавление нескольких серверов (IP/хост, SSH-порт, пользователь).
- Аутентификация по паролю **или** по приватному SSH-ключу.
- **Только контейнеры Amnezia**: в мониторинг попадают исключительно
  AmneziaWG / WireGuard / OpenVPN контейнеры Amnezia; посторонние образы
  (nginx, БД, pantera и т.п.) и сторонние VPN-стеки игнорируются.
- Для AmneziaWG / WireGuard: список пиров (пользователей) с endpoint, IP,
  последним хендшейком, статусом онлайн/офлайн и трафиком RX/TX.
- Для OpenVPN: список клиентов из `openvpn-status.log`.
- **История активности клиента**: по клику на пользователя открывается окно с
  его последними 10 запросами/событиями (подключение, отключение, смена
  endpoint, хендшейк) с временем и трафиком.
- **Отдельный таб «MTProto (Telegram)»**: список MTProto-прокси с их
  сгенерированными ключами и готовыми ссылками `t.me` / `tg://` (кнопка
  «Копировать ссылку»).
- **Установка AmneziaWG в один клик**: если на сервере нет контейнера
  `amnezia-awg`, панель показывает баннер **«⬇ Установить AmneziaWG»**. По кнопке
  панель скачивает образ `amneziavpn/amnezia-wg:latest`, генерирует ключи
  (`awg genkey`/`genpsk`), создаёт `awg0.conf` и запускает контейнер с теми же
  флагами, что и официальный установщик Amnezia.
- **Данные для подключения пользователя (аналог кнопки «Поделиться»)**: для
  каждого клиента кнопка **«🔗 Поделиться»** открывает окно с готовой
  конфигурацией WireGuard (`.conf`) и ссылкой `vpn://`, которую можно
  импортировать в приложение Amnezia. Кнопка **«➕ Создать подключение»**
  генерирует нового клиента и сразу выдаёт для него те же данные.
- Сводка: сколько контейнеров запущено, сколько пользователей онлайн и всего,
  сколько MTProto-прокси и ключей Telegram.
- Автообновление статуса раз в 15 секунд (переключается галочкой).

## Требования

- Node.js 18+
- Доступ по SSH к VPN-серверу(ам) с правами на `docker exec` (обычно `root`).
- На сервере установлен Docker с контейнерами Amnezia (`amnezia-awg`, `amnezia-wireguard`, `amnezia-openvpn` и т.п.).

## Установка и запуск

```bash
npm install
npm start
```

Панель будет доступна по адресу <http://localhost:3000>.

Порт можно изменить переменной окружения `PORT`. Самый удобный способ — файл
`.env` в корне проекта (он читается автоматически при старте через `dotenv`):

```bash
# .env
PORT=3600
```

Либо задать переменную прямо в команде запуска:

```bash
# Windows (cmd)
set PORT=3600 && npm start

# Linux / macOS
PORT=3600 npm start
```

## Использование

1. Откройте <http://localhost:3000>.
2. В блоке **«Добавить сервер»** укажите адрес сервера, SSH-порт (по умолчанию 22),
   пользователя и пароль (или приватный ключ) → **«Добавить сервер»**.
3. В списке серверов нажмите **«Мониторинг»** рядом с нужным сервером.
4. Ниже появится сводка и таблица по каждому Amnezia-контейнеру со списком клиентов.
5. **Нажмите на строку клиента** — откроется окно с последними 10 запросами/событиями
   этого пользователя.
6. **Кнопка «🔗 Поделиться»** в строке клиента — откроется окно с данными для
   подключения (аналог кнопки «Поделиться» в приложении Amnezia): ссылка `vpn://`
   для импорта и готовая конфигурация `.conf` с кнопками копирования.
7. Если контейнера AmneziaWG нет, появится баннер **«⬇ Установить AmneziaWG»**.
   Если клиент добавлен другим способом и его конфигурация не сохранена на сервере,
   используйте **«➕ Создать подключение»** — панель сгенерирует ключи и выдаст данные.
8. Переключитесь на вкладку **«✈️ MTProto (Telegram)»**, чтобы увидеть MTProto-прокси
   и их ключи Telegram со ссылками `t.me` / `tg://`.

### Формат ссылки `vpn://`

Ссылка совместима с приложением Amnezia и формируется так же, как в оригинальном
клиенте: `vpn://` + base64url(`qCompress(JSON, level=8)`), где `qCompress` —
это 4-байтовый big-endian размер + zlib-deflate на уровне 8. JSON повторяет
структуру `SelfHostedAdminServerConfig` (поле `format_version: 1`, контейнер
`amnezia-awg` с обфускационными параметрами AmneziaWG и вложенным `last_config`).
Полученную ссылку можно вставить в приложение Amnezia («Добавить VPN» → импорт).

### Как собирается история клиента

Amnezia VPN-контейнеры работают с драйвером логирования `none`, поэтому
`docker logs` для них пуст. Чтобы всё равно показывать «последние запросы»
пользователя, панель ведёт **собственный журнал активности**: при каждом сборе
статуса (ручное обновление или автообновление) событие клиента сохраняется в
`data/history.json`. В окне клиента показываются последние 10 событий, где о
событии менялось что-то значимое (онлайн/офлайн, endpoint, хендшейк, трафик).
Для контейнеров с обычным драйвером логов (например, MTProto) используется
резервный путь через `docker logs`.

## API

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/api/health` | Проверка работоспособности панели |
| `GET` | `/api/servers` | Список серверов (без секретов) |
| `POST` | `/api/servers` | Добавить сервер |
| `PUT` | `/api/servers/:id` | Изменить сервер |
| `DELETE` | `/api/servers/:id` | Удалить сервер (и его историю клиентов) |
| `GET` | `/api/servers/:id/status` | Собрать статус контейнеров, клиентов и MTProto-прокси |
| `GET` | `/api/servers/:id/logs` | Последние записи клиента. Параметры: `container` (обяз.), `id`, `client`, `endpoint` |
| `POST` | `/api/servers/:id/install-awg` | Установить и запустить контейнер `amnezia-awg`. Тело: `{ port?, subnet?, cidr? }` |
| `GET` | `/api/servers/:id/awg/config` | Данные для подключения (`.conf` + ссылка `vpn://`). Параметры: `container`, `id`/`client`, `clientIp`, `mode` (`existing`\|`new`), `dns1`, `dns2` |
| `GET` | `/api/servers/:id/awg/state` | Параметры сервера AmneziaWG (порт, подсеть, публичный ключ, число клиентов) |

## Структура проекта

```
server.js            # Express-приложение и REST API
src/ssh.js           # Выполнение команд по SSH (ssh2)
src/store.js         # Хранение серверов (data/servers.json)
src/parsers.js       # Парсеры вывода docker / awg / wg / OpenVPN / MTProto
src/collect.js       # Сбор и агрегация статуса сервера (Amnezia + MTProto)
src/awg.js           # Установка AmneziaWG и генерация данных для подключения (vpn://)
src/history.js       # Журнал активности клиентов (data/history.json)
public/              # Фронтенд (index.html, style.css, script.js)
data/servers.json    # Сохранённые серверы (создаётся автоматически, в git не попадает)
data/history.json    # История активности клиентов (создаётся автоматически, в git не попадает)
```

## Безопасность

- Учётные данные серверов хранятся в `data/servers.json` (файл создаётся с правами `600`
  и исключён из git через `.gitignore`).
- Секреты **никогда** не отдаются во фронтенд: API возвращает только флаги
  `hasPassword` / `hasKey`.
- Панель выполняет **только заранее заданные команды** (список ограничен в
  `src/collect.js`); произвольный ввод пользователя в shell не подставляется.
- Панель не имеет собственной аутентификации — **не выставляйте её в публичный
  интернет без дополнительной защиты** (VPN/SSH-туннель, reverse-proxy с
  Basic Auth и т.п.). Используйте доверенную сеть.

## Ограничения

- Поддерживаются AmneziaWG, WireGuard, OpenVPN (включая OpenVPN Cloak). Прочие
  протоколы Amnezia (Shadowsocks, Xray и др.) отображаются как контейнеры, но без
  детального списка клиентов. Контейнеры сторонних VPN-стеков не показываются.
- Имена пользователей берутся из комментариев в `.conf`
  (`# Имя`) и из `clientsTable`. Если имя не найдено, клиент показывается как
  `peer-N`.
- Для OpenVPN требуется, чтобы на сервере писался `openvpn-status.log`.
- «Последние 10 запросов» клиента — это события активности, накопленные панелью
  между обновлениями статуса (`data/history.json`), а не сырой лог трафика.
  История наполняется только пока за сервером ведётся мониторинг.
- MTProto-ключи извлекаются из переменной окружения `SECRET`, из логов
  контейнера и из `telemt.toml` (`[access.users]`). Ссылки `t.me`/`tg://`
  строятся с внешним адресом и портом сервера.
