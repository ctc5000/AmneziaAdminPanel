# Amnezia VPN Control Panel

Веб-панель для мониторинга VPN-серверов Amnezia: отслеживает **состояние
Docker-контейнеров** и **список подключённых пользователей** (клиентов) на
каждом сервере.

Работает так: панель по SSH заходит на сервер, выполняет команды `docker` и
`awg`/`wg`/OpenVPN-status, парсит вывод и показывает результат в браузере.

## Возможности

- **Ролевая модель с пользователями**: при первом запуске создаётся учётная
  запись администратора; вход в панель — по логину и паролю (сессии на cookie).
- **Самостоятельная регистрация**: любой может создать себе аккаунт на странице
  входа (ссылка «Зарегистрироваться»). Новый аккаунт **всегда** получает роль
  `user`; роль admin присваивается администратором — через окно «👥 Пользователи»
  или **правкой файла `data/users.json`** (файл перечитывается на лету, без
  перезапуска панели).
  - **Администратор** видит всё: список серверов с полным мониторингом
    контейнеров и клиентов, MTProto-ключи, историю активности, установку
    AmneziaWG, добавление/изменение/удаление серверов и управление
    пользователями. Дополнительно администратор решает, **какие серверы видят
    обычные пользователи** (переключатель «Показывать пользователям» на карточке
    сервера или галочка в форме сервера).
  - **Пользователь** видит только разрешённые (видимые) серверы и может
    **создавать подключения**: AmneziaWG (`vpn://`-ссылка и `.conf`) и
    подключение к MTProto-прокси (ссылка `t.me`/`tg://`). Полное состояние
    контейнеров, ключи и история клиентов пользователю недоступны.
- **Пинг до каждого сервера** отображается значком на карточке (RTT в мс и
  процент потерь), для администратора доступна предварительная проверка пинга
  при добавлении сервера.
- Добавление нескольких серверов (IP/хост, SSH-порт, пользователь).
- Аутентификация по паролю **или** по приватному SSH-ключу.
- **Только контейнеры Amnezia**: в мониторинг попадают исключительно
  AmneziaWG / WireGuard / OpenVPN контейнеры Amnezia; посторонние образы
  (nginx, БД, pantera и т.п.) и сторонние VPN-стеки игнорируются.
- Для AmneziaWG / WireGuard: список пиров (пользователей) с endpoint, IP,
  последним хендшейком, статусом онлайн/офлайн и трафиком RX/TX.
- Для OpenVPN: список клиентов из `openvpn-status.log`.
- **История активности клиента**: по клику на пользователя открывается окно с
  его последними 10 запросами/событиями (подключение, отключение, смена
  endpoint, хендшейк) с временем и трафиком.
- **Отдельный таб «MTProto (Telegram)»**: список MTProto-прокси с их
  сгенерированными ключами и готовыми ссылками `t.me` / `tg://` (кнопка
  «Копировать ссылку»).
- **Установка AmneziaWG в один клик**: если на сервере нет контейнера
  `amnezia-awg`, панель показывает баннер **«⬇ Установить AmneziaWG»**. По кнопке
  панель скачивает образ `amneziavpn/amnezia-wg:latest`, генерирует ключи
  (`awg genkey`/`genpsk`), создаёт `awg0.conf` и запускает контейнер с теми же
  флагами, что и официальный установщик Amnezia.
- **Данные для подключения пользователя (аналог кнопки «Поделиться»)**: для
  каждого клиента кнопка **«🔗 Поделиться»** открывает окно с готовой
  конфигурацией WireGuard (`.conf`) и ссылкой `vpn://`, которую можно
  импортировать в приложение Amnezia. Кнопка **«➕ Создать подключение»**
  генерирует нового клиента и сразу выдаёт для него те же данные.
- Сводка: сколько контейнеров запущено, сколько пользователей онлайн и всего,
  сколько MTProto-прокси и ключей Telegram.
- Автообновление статуса раз в 15 секунд (переключается галочкой).

## Требования

- Node.js 18+
- Доступ по SSH к VPN-серверу(ам) с правами на `docker exec` (обычно `root`).
- На сервере установлен Docker с контейнерами Amnezia (`amnezia-awg`, `amnezia-wireguard`, `amnezia-openvpn` и т.п.).

## Установка и запуск

```bash
npm install
npm start
```

Панель будет доступна по адресу <http://localhost:3000>.

Порт можно изменить переменной окружения `PORT`. Самый удобный способ — файл
`.env` в корне проекта (он читается автоматически при старте через `dotenv`):

```bash
# .env
PORT=3600

# Первичная учётная запись администратора (создаётся только при первом запуске,
# когда файла data/users.json ещё нет).
ADMIN_USERNAME=admin
ADMIN_PASSWORD=change-me-please
```

Если `ADMIN_USERNAME` / `ADMIN_PASSWORD` не заданы, при первом запуске
создаётся администратор **`admin` / `admin`** — обязательно смените пароль
сразу после входа через окно **«👥 Пользователи»**.

Либо задать переменную прямо в команде запуска:

```bash
# Windows (cmd)
set PORT=3600 && npm start

# Linux / macOS
PORT=3600 npm start
```

## Использование

1. Откройте <http://localhost:3000> и войдите под администратором (по умолчанию
   `admin` / `admin`, если не заданы переменные окружения).
2. В блоке **«➕ Добавить сервер»** укажите адрес сервера, SSH-порт (по умолчанию 22),
   пользователя и пароль (или приватный ключ) → **«Сохранить»**. Галочкой
   **«Показывать этот сервер пользователям»** сразу решите, будет ли он виден
   обычным пользователям.
3. В списке серверов нажмите на нужный сервер.
4. Ниже появится сводка и таблица по каждому Amnezia-контейнеру со списком клиентов.
5. **Нажмите на строку клиента** — откроется окно с последними 10 запросами/событиями
   этого пользователя.
6. **Кнопка «🔗 Поделиться»** в строке клиента — откроется окно с данными для
   подключения (аналог кнопки «Поделиться» в приложении Amnezia): ссылка `vpn://`
   для импорта и готовая конфигурация `.conf` с кнопками копирования.
7. Если контейнера AmneziaWG нет, появится баннер **«⬇ Установить AmneziaWG»**.
   Если клиент добавлен другим способом и его конфигурация не сохранена на сервере,
   используйте **«➕ Создать подключение»** — панель сгенерирует ключи и выдаст данные.
8. Переключитесь на вкладку **«✈️ MTProto (Telegram)»**, чтобы увидеть MTProto-прокси
   и их ключи Telegram со ссылками `t.me` / `tg://`.

### Регистрация и роли

- На странице входа есть ссылка **«Зарегистрироваться»**. Любой пользователь может
  создать себе аккаунт: он сразу входит в панель и получает роль **`user`**
  (только список разрешённых серверов и кнопки создания подключений).
- Роль **`admin`** выдаётся администратором одним из двух способов:
  1. Через окно **«👥 Пользователи»** — смена роли в выпадающем списке.
  2. **Правкой файла `data/users.json`** — измените значение `"role"` нужного
     пользователя на `"admin"`. Панель перечитывает файл при каждом запросе,
     так что перезапуск не нужен. Формат записи:

     ```json
     {
       "id": "…",
       "username": "ivan",
       "passwordHash": "scrypt:…:…",
       "role": "admin",
       "createdAt": "2026-01-01T00:00:00.000Z"
     }
     ```

- Роль пользователя применяется к его текущей сессии на следующем запросе
  (перезаходить не требуется).
- Нельзя удалить или понизить последнего администратора — это защищает панель от
  полной потери доступа.

### Управление пользователями и видимостью (администратор)

- Кнопка **«👥 Пользователи»** в шапке открывает окно управления доступом: список
  учётных записей с ролями, добавление нового пользователя (логин, пароль, роль),
  смена роли и сброс пароля.
- Видимость сервера для пользователей переключается кнопкой **«👁 Показать
  пользователям» / «🚫 Скрыть от пользователей»** прямо на карточке сервера, а
  также галочкой при добавлении/редактировании сервера. По умолчанию новые
  серверы **скрыты** от пользователей.
- Нельзя удалить или понизить последнего администратора — это защищает панель от
  полной потери доступа.

### Интерфейс пользователя

Обычный пользователь после входа видит только разрешённые серверы. На карточке
каждого сервера отображается пинг и две кнопки:

- **«➕ AmneziaWG»** — создаёт новое подключение AmneziaWG и показывает `vpn://`-ссылку
  и `.conf` для импорта в приложение Amnezia.
- **«🔗 Прокси»** — открывает данные для подключения к MTProto-прокси (Telegram)
  со ссылкой `t.me` / `tg://` и кнопкой копирования.

Полное состояние контейнеров, список клиентов, история активности и MTProto-ключи
пользователю недоступны.

### Формат ссылки `vpn://`

Ссылка совместима с приложением Amnezia и формируется так же, как в оригинальном
клиенте: `vpn://` + base64url(`qCompress(JSON, level=8)`), где `qCompress` —
это 4-байтовый big-endian размер + zlib-deflate на уровне 8. JSON повторяет
структуру `SelfHostedAdminServerConfig` (поле `format_version: 1`, контейнер
`amnezia-awg` с обфускационными параметрами AmneziaWG и вложенным `last_config`).
Полученную ссылку можно вставить в приложение Amnezia («Добавить VPN» → импорт).

### Как собирается история клиента

Amnezia VPN-контейнеры работают с драйвером логирования `none`, поэтому
`docker logs` для них пуст. Чтобы всё равно показывать «последние запросы»
пользователя, панель ведёт **собственный журнал активности**: при каждом сборе
статуса (ручное обновление или автообновление) событие клиента сохраняется в
`data/history.json`. В окне клиента показываются последние 10 событий, где о
событии менялось что-то значимое (онлайн/офлайн, endpoint, хендшейк, трафик).
Для контейнеров с обычным драйвером логов (например, MTProto) используется
резервный путь через `docker logs`.

## API

Все маршруты, кроме `/api/health` и `/api/auth/*`, требуют активной сессии
(авторизации). Маршруты, помеченные **admin**, доступны только администраторам.

| Метод | Путь | Доступ | Описание |
|-------|------|--------|----------|
| `GET` | `/api/health` | все | Проверка работоспособности панели |
| `POST` | `/api/auth/register` | все | Самостоятельная регистрация (роль `user`). Тело: `{ username, password }` |
| `POST` | `/api/auth/login` | все | Вход. Тело: `{ username, password }` |
| `POST` | `/api/auth/logout` | сессия | Выход (сброс сессионной cookie) |
| `GET` | `/api/auth/me` | сессия | Текущий пользователь (`{ id, username, role }`) |
| `GET` | `/api/servers` | сессия | Список серверов (без секретов). Пользователи видят только видимые серверы |
| `POST` | `/api/servers` | admin | Добавить сервер |
| `PUT` | `/api/servers/:id` | admin | Изменить сервер (в т.ч. видимость) |
| `DELETE` | `/api/servers/:id` | admin | Удалить сервер (и его историю клиентов) |
| `GET` | `/api/servers/:id/ping` | сессия | Пинг доступного сервера (RTT, потери) |
| `POST` | `/api/servers/ping` | admin | Предварительный пинг произвольного адреса (до добавления сервера) |
| `GET` | `/api/servers/:id/status` | admin | Собрать статус контейнеров, клиентов и MTProto-прокси |
| `GET` | `/api/servers/:id/logs` | admin | Последние записи клиента. Параметры: `container` (обяз.), `id`, `client`, `endpoint` |
| `POST` | `/api/servers/:id/install-awg` | admin | Установить и запустить контейнер `amnezia-awg`. Тело: `{ port?, subnet?, cidr? }` |
| `GET` | `/api/servers/:id/proxies` | сессия | Список доступных подключений (AmneziaWG / MTProto) для видимого сервера |
| `GET` | `/api/servers/:id/awg/config` | сессия | Данные для подключения (`.conf` + ссылка `vpn://`). Параметры: `container`, `id`/`client`, `clientIp`, `mode` (`existing`\|`new`), `dns1`, `dns2` |
| `GET` | `/api/servers/:id/awg/state` | admin | Параметры сервера AmneziaWG (порт, подсеть, публичный ключ, число клиентов) |
| `GET` | `/api/servers/:id/mtproto/config` | сессия | Данные MTProto-прокси (host, port, secret, ссылка `t.me`/`tg://`). Параметр `name` |
| `GET` | `/api/users` | admin | Список пользователей (без хешей паролей) |
| `POST` | `/api/users` | admin | Создать пользователя. Тело: `{ username, password, role }` |
| `PUT` | `/api/users/:id` | admin | Изменить роль и/или пароль |
| `DELETE` | `/api/users/:id` | admin | Удалить пользователя |

## Структура проекта

```
server.js            # Express-приложение и REST API
src/ssh.js           # Выполнение команд по SSH (ssh2)
src/store.js         # Хранение серверов (data/servers.json)
src/users.js         # Пользователи и роли, хеширование паролей (data/users.json)
src/auth.js          # Сессии и middleware авторизации (cookie + requireAuth/requireAdmin)
src/ping.js          # ICMP/TCP-пинг до серверов
src/parsers.js       # Парсеры вывода docker / awg / wg / OpenVPN / MTProto
src/collect.js       # Сбор и агрегация статуса сервера (Amnezia + MTProto)
src/awg.js           # Установка AmneziaWG и генерация данных для подключения (vpn://)
src/history.js       # Журнал активности клиентов (data/history.json)
public/              # Фронтенд (index.html, style.css, script.js)
data/servers.json    # Сохранённые серверы (создаётся автоматически, в git не попадает)
data/users.json      # Пользователи и хеши паролей (создаётся автоматически, в git не попадает)
data/history.json    # История активности клиентов (создаётся автоматически, в git не попадает)
```

## Безопасность

- Учётные данные серверов хранятся в `data/servers.json` (файл создаётся с правами `600`
  и исключён из git через `.gitignore`).
- Пользователи хранятся в `data/users.json` (права `600`, исключён из git). Пароли
  хранятся **только в виде хеша** (scrypt со случайной солью) и сравниваются
  устойчиво ко времени (`crypto.timingSafeEqual`). Хеши никогда не покидают сервер.
- Самостоятельная регистрация не позволяет выбрать роль: новый аккаунт всегда
  `user`. Файл `data/users.json` перечитывается на лету, поэтому правка ролей в нём
  вступает в силу без перезапуска панели.
- Аутентификация — сессионная, на HttpOnly-cookie (`SameSite=Lax`), срок жизни
  сессии 7 дней. Cookie не содержит учётных данных.
- Доступ к серверам разграничен по ролям: пользователь может обращаться только к
  **видимым** серверам и только к маршрутам, выдающим данные для подключения
  (AmneziaWG/MTProto); статус, логи, установка и история контейнеров — только для
  администратора.
- Секреты серверов **никогда** не отдаются во фронтенд: API возвращает только флаги
  `hasPassword` / `hasKey`.
- Панель выполняет **только заранее заданные команды** (список ограничен в
  `src/collect.js`); произвольный ввод пользователя в shell не подставляется.
- Всё равно **не выставляйте панель в публичный интернет без дополнительной
  защиты** — используйте HTTPS (reverse-proxy), VPN/SSH-туннель или ограничение
  по IP.

## Ограничения

- Поддерживаются AmneziaWG, WireGuard, OpenVPN (включая OpenVPN Cloak). Прочие
  протоколы Amnezia (Shadowsocks, Xray и др.) отображаются как контейнеры, но без
  детального списка клиентов. Контейнеры сторонних VPN-стеков не показываются.
- Имена пользователей берутся из комментариев в `.conf`
  (`# Имя`) и из `clientsTable`. Если имя не найдено, клиент показывается как
  `peer-N`.
- Для OpenVPN требуется, чтобы на сервере писался `openvpn-status.log`.
- «Последние 10 запросов» клиента — это события активности, накопленные панелью
  между обновлениями статуса (`data/history.json`), а не сырой лог трафика.
  История наполняется только пока за сервером ведётся мониторинг.
- MTProto-ключи извлекаются из переменной окружения `SECRET`, из логов
  контейнера и из `telemt.toml` (`[access.users]`). Ссылки `t.me`/`tg://`
  строятся с внешним адресом и портом сервера.
